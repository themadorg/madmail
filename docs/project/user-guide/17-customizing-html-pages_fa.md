# سفارشی‌سازی صفحات HTML و رابط تحت وب

هر سرور chatmail یک رابط وب عمومی ارائه می‌دهد. این رابط شامل صفحه اصلی، ثبت‌نام (`/new`)، اشتراک‌گذاری مخاطب، صفحات دعوت، مستندات در مسیر `/docs/` و سایر دارایی‌ها (assets) است.

به‌صورت پیش‌فرض از صفحات توکار همراه با سرور استفاده می‌شود. شما می‌توانید این صفحات را متناسب با برندسازی، زبان یا نیازمندی‌های خود سفارشی‌سازی کنید.

## چرا HTML را سفارشی‌سازی کنیم؟

دلایل رایج عبارتند از:

- افزودن لوگو، رنگ‌ها یا برندسازی دامنه اختصاصی خود.
- ارائه دستورالعمل‌ها به زبان محلی شما.
- افزودن قوانین مشخص، اطلاعیه‌های حقوقی یا اطلاعات تماس.
- ایجاد یک ظاهر عمومی مینیمال یا «پنهان» (stealth).
- میزبانی نسخه سفارشی‌سازی‌شده خودتان از مستندات.

## نحوه کارکرد

سرور از تنظیمی به نام `www_dir` پشتیبانی می‌کند. هنگامی که این گزینه پیکربندی شود، سرور ابتدا به دنبال فایل‌ها در دایرکتوری سفارشی شما می‌گردد. اگر فایل درخواستی در آنجا پیدا نشود، به نسخه توکار برمی‌گردد (fallback).

این بدان معناست که تنها کافی است فایل‌هایی را که قصد تغییرشان را دارید فراهم کنید — همه چیز دیگر به کار عادی خود ادامه می‌دهد.

### تنظیم یک دایرکتوری WWW سفارشی

**Linux** — افزودن به فایل پیکربندی (مثال مسیر):

```toml
www_dir = "/var/lib/madmail/www"
```

یا با استفاده از CLI:

```bash
# Linux
sudo madmail html-serve /var/lib/madmail/www

# Windows (elevated PowerShell; ProgramData layout)
& "C:\Program Files\Madmail\madmail.exe" `
  --config "$env:ProgramData\Madmail\config\madmail.conf" `
  --state-dir "$env:ProgramData\Madmail\data" `
  html-serve "$env:ProgramData\Madmail\www"
```

برای بازگشت به فایل‌های توکار (تعبیه‌شده):

```bash
madmail html-serve embedded
# Windows: same command with --config / --state-dir as above
```

سپس پیکربندی را اعمال کنید:

```bash
# Linux
sudo madmail reload
# or: sudo systemctl reload madmail / restart madmail

# Windows
Restart-Service Madmail
# or: madmail … reload  (then restart service if routes did not remount)
```

مطمئن شوید که دایرکتوری توسط حسابی که سرویس با آن اجرا می‌شود قابل خواندن است:

| پلتفرم | حساب سرویس معمول | نکات |
|----------|-------------------------|--------|
| Linux | کاربر سیستمی `madmail` | دستور `chown` / مجوزها روی `www_dir` |
| Windows | **LocalSystem** (سرویس پیش‌فرض SCM) | مسیرهای زیر `%ProgramData%\Madmail\` مشکلی ندارند؛ اگر `www` را در جای دیگری قرار دادید، مجوز **Read** + پیمایش (traverse) بدهید |

## شروع سفارشی‌سازی

### Linux

1. یک دایرکتوری ایجاد کنید (مثلاً `/var/lib/madmail/www`).
2. خروجی گرفتن از فایل‌های پیش‌فرض: `sudo madmail html-export /var/lib/madmail/www`
3. فایل‌های مورد نظر خود را ویرایش کنید.
4. دستور `sudo madmail html-serve /var/lib/madmail/www` و سپس `sudo madmail reload` (یا ری‌استارت کردن واحد سرویس).

### Windows

1. مسیر `%ProgramData%\Madmail\www` را بسازید (یا مسیر دیگری که LocalSystem بتواند بخواند).
2. خروجی گرفتن از فایل‌های پیش‌فرض (با دسترسی ادمین):

```powershell
$cfg = "$env:ProgramData\Madmail\config\madmail.conf"
$st  = "$env:ProgramData\Madmail\data"
$www = "$env:ProgramData\Madmail\www"
New-Item -ItemType Directory -Force -Path $www | Out-Null
& "C:\Program Files\Madmail\madmail.exe" --config $cfg --state-dir $st html-export $www
& "C:\Program Files\Madmail\madmail.exe" --config $cfg --state-dir $st html-serve $www
Restart-Service Madmail
```

3. فایل‌های زیر `$www` را ویرایش کنید و مرورگر را هارد رفرش کنید (Ctrl+Shift+R).
4. بازگردانی به حالت قبل: دستور `html-serve embedded` + ری‌استارت سرویس.

بسیاری از مدیران سرور یک بار کل ساختار درختی پیش‌فرض را خروجی می‌گیرند (**export**) و سپس به مرور زمان فایل‌های مدنظر را جایگزین می‌کنند. فایل‌های ناموجود همچنان به مقادیر پیش‌فرض توکار برمی‌گردند.

### ساختار پیشنهادی در Windows

```text
%ProgramData%\Madmail\
  config\madmail.conf     ← www_dir set by html-serve
  www\                    ← editable HTML/CSS/JS
  data\                   ← mail DB, admin_token (do not put secrets in www\)
```

## چه مواردی را می‌توانید سفارشی‌سازی کنید

شما می‌توانید اکثر صفحات و دارایی‌های عمومی را بازنویسی (override) کنید، از جمله:

- صفحه اصلی فرود (`index.html`)
- صفحات ثبت‌نام و دعوت
- صفحات اشتراک‌گذاری مخاطب (`/share`)
- صفحات مستندات زیر مسیر `/docs/`
- فایل‌های CSS، تصاویر و جاوااسکریپت
- صفحات خطا

این موضوع بدون نیاز به تغییر دادن باینری سرور، انعطاف‌پذیری زیادی به شما می‌دهد.

## مستندات خود سرور

هر سرور در حال اجرای chatmail مجموعه‌ای کامل از مستندات را نیز در آدرس زیر ارائه می‌دهد:

```
https://your-server/docs/
```

این مستندات چندزبانه هستند و شامل راهنمایی به‌طور خاص در مورد سفارشی‌سازی HTML می‌شوند (معمولاً در مسیری مانند `/docs/custom-html` در دسترس است).

این راهنمای توکار با نسخه سرور در حال اجرا مطابقت دارد و مشخص می‌کند کدام فایل‌ها را می‌توانید بازنویسی کنید و چه امکانات ویژه‌ای در دسترس است.

## ملاحظات امنیتی

- سرور هر فایل استاتیکی را که در `www_dir` پیدا کند ارائه می‌دهد. فایل‌های حساس (کلیدهای خصوصی، فایل‌های پایگاه داده، لاگ‌ها و غیره) را در این دایرکتوری قرار ندهید.
- اگر از TLS استفاده می‌کنید (به‌شدت توصیه می‌شود)، صفحات سفارشی‌سازی‌شده شما از طریق HTTPS ارائه خواهند شد.
- مراقب جاوااسکریپت و فرم‌ها باشید — هر کد سفارشی در مرورگر کاربر با همان مبدأ (origin) سرور شما اجرا می‌شود.

## به‌روزرسانی پس از اعمال تغییرات

پس از ویرایش‌های **محتوایی** زیر یک `www_dir` موجود، سرور مجدداً HTML را از روی دیسک می‌خواند؛ به ندرت به ری‌استارت کامل نیاز است. پس از اجرای **`html-serve`** (تغییر مسیر یا جابه‌جایی به حالت `embedded`)، دستور **`madmail reload`** را اجرا کنید و/یا سرویس را ری‌استارت کنید (`systemctl restart madmail` / `Restart-Service Madmail`).

کاربران ممکن است برای مشاهده دارایی‌های استاتیک به‌روزرسانی‌شده، نیاز به هارد رفرش در مرورگر (Ctrl+Shift+R یا Cmd+Shift+R) داشته باشند.

## نسخه Go Madmail ← madmail-v2 (سینتکس قالب‌ها)

صفحات قدیمی Go Madmail از نشانه‌گذارهای `html/template` مربوط به Go مانند `{{if .RegistrationOpen}}`، **`{{if not .RegistrationOpen}}`** و `{{.MailDomain | cleanDomain}}` استفاده می‌کردند. نسخه madmail-v2 با استفاده از **Minijinja** رندر می‌کند (`{% if RegistrationOpen %}`، `{% if not RegistrationOpen %}`، `{{ MailDomain | clean_domain }}`).

رها کردن عبارات `{{if not .…}}` در Go بدون تبدیل، باعث بروز خطاهای قالب (`unexpected '.'`) می‌شد. تبدیل در زمان اجرا (runtime) و `html-migrate` هر دو از این الگو پشتیبانی و آن را مدیریت می‌کنند.

اگر یک `www_dir` سفارشی‌سازی‌شده از نسخه Go Madmail نگه‌داشته‌اید:

1. پس از ارتقای باینری، دستورات `madmail update` / `upgrade` پیشنهاد تبدیل آن فایل‌ها را ارائه می‌دهند (یا خودتان دستور `madmail html-migrate` را اجرا کنید).
2. با تأیید آن، فایل‌های پشتیبان `*.go-template.bak` ساخته شده و HTML در جای خود بازنویسی می‌شود.
3. سرور همچنان می‌تواند بسیاری از ساختارهای Go را در زمان رندر تبدیل کند، اما مهاجرت آن‌ها روی دیسک، سورس‌های شما را با موتور نسخه v2 سازگار نگه می‌دارد.
4. همین دستور استفاده از **QR کد قدیمی** را نیز اصلاح می‌کند (`/qr?data=…` ← به سمت کلاینت `setQrCodeImage` + `qrcode.min.js`). اندپوینت قدیمی HTTP با مسیر `/qr` حذف شده است.

مرجع CLI را ببینید: [html-migrate](../../guide/cli/html-migrate.md).

## کاراکترهای دقیق `{%` و `{{` در HTML سفارشی (آدرس‌های اینترنتی Obtainium و غیره)

موتور Minijinja با **`{%`** و **`{{`** در همه‌جای فایل به‌عنوان سینتکس قالب رفتار می‌کند — از جمله درون `href`، اسکریپت‌ها و متن ساده.

این رفتار باعث خراب شدن صفحات سفارشی می‌شود که دارای لینک‌های عمیق (deep links) یا آدرس‌های فروشگاه برنامه حاوی این توالی‌ها هستند. یک مورد رایج لینک‌های سبک **Obtainium** است که در آن‌ها کدگذاری URL توالی `{%22` (یک `{` به دنبال `%22…`) تولید می‌کند.

**علائم:** خطای HTTP 500 در صفحه؛ لاگ‌هایی مانند `www template render` / `syntax error` با ذکر نام فایل.

**راه‌حل:** محتوای دقیق را درون بلوک خام (raw) بپوشانید تا موتور قالب آن را تجزیه نکند:

```html
{% raw %}
<a href="https://example.com/install?config={%22id%22:%22app%22}">Download</a>
{% endraw %}
```

دستور `html-migrate` درباره توالی‌های مشکوک `{%` / `{{` **هشدار می‌دهد** اما آن‌ها را به‌صورت خودکار در بلوک خام **نمی‌پوشاند** (زیرا ممکن است قالب‌های واقعی را خراب کند). پس از ویرایش، سرویس را ریلود یا ری‌استارت کنید.

## مثال‌های رایج

- سرورهای اجتماعی که قوانین محلی و اطلاعات تماس پشتیبانی را اضافه می‌کنند.
- سازمان‌هایی که برند سازمانی خود را اعمال می‌کنند.
- مدیران در مناطق دارای محدودیت که ضمن حفظ کامل قابلیت‌ها، حضور عمومی سرور را به حداقل می‌رسانند.
- ارائه مستندات ترجمه‌شده متناسب با کاربران محلی.

## مطالعه بیشتر

مرجع ارائه‌شده همراه با سرور در حال اجرای شما در مسیر `/docs/custom-html` (یا مسیر معادل) قرار دارد. این مستندات مطابق با نسخه madmail نصب‌شده شما است.

همچنین می‌توانید دایرکتوری `www-src/` را در کد منبع بررسی کنید تا ساختار و قالب‌های پیش‌فرض را مشاهده نمایید.
