# شروع سریع: راه‌اندازی یک سرور چتمیل

این راهنما راه‌اندازی سرور چتمیل را از آزمایش محلی تا استفادهٔ عمومی توضیح می‌دهد.

> در مثال‌ها، `--lang en` رابط وب سرور را انگلیسی می‌کند. برای رابط فارسی از `--lang fa` استفاده کنید.

## راه‌اندازی سریع

فایل اجرایی مناسب معماری سرور را دانلود کنید؛ سپس سرویس را نصب و راه‌اندازی کنید:

```bash
ARCH=$(uname -m | sed 's/x86_64/amd64/;s/aarch64/arm64/')
curl -fsSL "https://github.com/themadorg/madmail/releases/latest/download/madmail-linux-${ARCH}" \
  -o madmail
chmod +x madmail
```

### با IP عمومی (بدون دامنه)

استفاده از TLS معتبر از طریق گواهی IP ارائه‌شده توسط Let's Encrypt (تمدید حدوداً ۶ روزه، نیازمند پورت 80):

```bash
sudo ./madmail install --simple --ip YOUR_IP \
  --auto-ip-cert \
  --acme-email you@example.com \
  --lang en
sudo systemctl enable madmail
sudo systemctl start madmail
```

> عبارت `YOUR_IP` را با آدرس عمومی IPv4 یا IPv6 سرور خود جایگزین کنید.

گواهی TLS خودامضا (آزمایشی / داخلی — بدون پرچم `--auto-ip-cert`):

```bash
sudo ./madmail install --simple --ip YOUR_IP --lang en
sudo systemctl enable madmail
sudo systemctl start madmail
```

### با دامنه

گواهی استاندارد Let's Encrypt (تمدید ۹۰ روزه، DNS باید به سرور شما اشاره کند):

```bash
sudo ./madmail install --simple --domain mail.example.org \
  --acme-email you@example.com \
  --lang en
sudo systemctl enable madmail
sudo systemctl start madmail
```

> عبارت `mail.example.org` را با نام هاست خود و `you@example.com` را با یک ایمیل تماس معتبر جایگزین کنید.

پیش از نصب، یک رکورد **`A`/`AAAA`** برای نام هاست ایجاد کنید که به سرور شما اشاره داشته باشد. پس از نصب، رکورد **`MX`** و (در صورت تمایل) رکوردهای SPF/DKIM/DMARC را اضافه کنید — به [DNS و احراز هویت ایمیل](./12-dns-mail-auth.md) مراجعه کنید.

اگر هر دو رکورد A و AAAA وجود داشته باشند و `--ip` را مشخص نکنید، عملیات نصب در صورت در دسترس بودن، مقدار `$(public_ip)` (برای TURN / کشف سرویس) را از یک **IPv4 عمومی** تنظیم می‌کند. برای اعلام IPv6 به عنوان آدرس TURN، پرچم `--ip` را همراه با آن آدرس ارسال کنید.

### مسیرهای سفارشی و تعمیر هدفمند

برای ایجاد یک سرویس جدید Unix در مسیرهای سفارشی، پرچم `--system` را به‌طور صریح انتخاب کنید:

```bash
sudo ./madmail install --simple --system --domain mail.example.org \
  --acme-email admin@example.org \
  --config-dir /var/xyzzy/etc/madmail --state-dir /var/xyzzy/lib/madmail \
  --binary-path /var/xyzzy/bin/madmail --dry-run
```

طرح نصب را بررسی کنید، دستور را بدون `--dry-run` دوباره اجرا نمایید، سپس دستور `sudo systemctl enable --now madmail` را وارد کنید.
برای راه‌اندازی اولیه نرم‌افزار بدون ایجاد کاربران میزبان یا تغییرات در systemd، از `--local` استفاده کنید.
اجرای دستور صرفاً با دسترسی root، حالت سیستمی را برای مسیرهای سفارشی فعال نمی‌کند.

برای یک **نصب موجود**، جهت رفع اشکال حساب کاربری یا واحد سرویس، از اجرای مجدد راه‌اندازی اولیه کامل خودداری کنید. سرویس را در صورت فعال بودن متوقف کرده و سپس عملیات تعمیر مورد نیاز را اجرا نمایید:

```bash
sudo ./madmail install --user-only \
  --config-dir /var/xyzzy/etc/madmail --state-dir /var/xyzzy/lib/madmail
sudo ./madmail install --systemd-only \
  --config-dir /var/xyzzy/etc/madmail --state-dir /var/xyzzy/lib/madmail \
  --binary-path /var/xyzzy/bin/madmail
```

تعمیر حساب، کاربر/گروه و مجوزها را اصلاح می‌کند. تعمیر واحد سرویس، فایل واحد را جایگزین کرده و systemd را مجدداً بارگذاری (reload) می‌کند. هر دو روش محتوای پیکربندی، پایگاه داده، گواهی و فایل‌های باینری را دست‌نخورده نگه می‌دارند؛ پس از آن سرویس را به‌طور صریح آغاز کنید. از نام فایل اجرایی و مسیرهای اصلی استفاده نمایید.

[مرجع کامل CLI و تمام پرچم‌ها](../../guide/cli/install.md) · [مقایسه حالت‌ها](../../guide/cli/install.md#choose-the-operation) · [پیش‌نیازهای تعمیر](../../guide/cli/install.md#repair-only-the-service-account-or-systemd-unit)

### Windows

در صورت در دسترس بودن، ترجیحاً از **ویزارد راه‌اندازی** استفاده کنید (`madmail-windows-amd64-setup.exe` از بخش دارایی‌های **Release** گیت‌هاب)، یا از CLI بهره ببرید.

**UAC / SmartScreen / Defender:** باینری‌ها **امضا نشده** (unsigned) هستند. درخواست UAC را تأیید کنید (**Yes** / اجرای راه‌اندازی با **run as administrator**). اگر SmartScreen پیام «Windows protected your PC» را نمایش داد، گزینه **More info → Run anyway** را فقط برای فایل‌هایی که از این مخزن مورد اعتماد شما هستند استفاده کنید. ممکن است Defender هشدار مثبت کاذب بدهد (مانند Bearfoos) — برای استثنائات و مراحل بازیابی: [packaging/windows/README.md](../../../packaging/windows/README.md#windows-defender-smartscreen-and-uac).

```powershell
# After placing madmail.exe on the machine (elevated PowerShell recommended)
.\madmail.exe install --simple --ip YOUR_IP --tls-mode self_signed --lang en `
  --install-service --start-service --firewall

# Optional tray
.\madmail-tray.exe install-autostart
.\madmail-tray.exe
```

پیش‌فرض‌ها:

| مورد | مسیر |
|------|------|
| پیکربندی / گواهی‌ها | `%ProgramData%\Madmail\config\` |
| وضعیت / توکن | `%ProgramData%\Madmail\data\` |
| نام سرویس | `Madmail` |

دستورات کاربردی: `madmail service status`،‏ `madmail admin-token`،‏ `madmail firewall apply`،‏ `madmail-tray --smoke-exit`.

مدیریت: از **CLI** و **`POST /api/admin`** به همراه توکن حامل (bearer token) استفاده کنید. بسته‌های فعلی Windows فاقد SPA مدیریت تحت وب (admin-web) در مسیر `/admin` هستند (درخواست مرورگر از نوع GET روی مسیر `/api/admin` خطای **405** برمی‌گرداند).

**HTML عمومی سفارشی** (`/`، `/new`، `/docs/`، …): فایل‌های پیش‌فرض را به `%ProgramData%\Madmail\www` استخراج کنید، دستور `html-serve` را اجرا کرده و سرویس را مجدداً راه‌اندازی نمایید — به [سفارشی‌سازی صفحات HTML](./17-customizing-html-pages.md#windows) مراجعه کنید.

## تست محلی (برای اپراتورها)

← **[گردش کار توسعه محلی](../15-development-workflow.md)**

آن راهنما چرخه کامل ویرایش ← ساخت ← تست را که توسط افراد فعال روی کد madmail-v2 استفاده می‌شود، پوشش می‌دهد.

## دریافت باینری از پیش ساخته‌شده (Releases)

برای دریافت یک باینری آماده استفاده بدون نیاز به کامپایل:

1. به صفحه نسخه‌های منتشرشده بروید:\
   **https://github.com/themadorg/madmail/releases**

2. آخرین نسخه منتشرشده مناسب برای معماری خود را دانلود کنید. نسخه‌های منتشرشده شامل چندین نگارش لینوکس و یک نصاب Windows هستند:

   | فایل (Asset) | زمان استفاده |
   |-------|----------|
   | `madmail-linux-amd64` / `.tar.gz` | Debian 13، Ubuntu 24.04، Ubuntu 26.04 و AlmaLinux 10 |
   | `madmail-linux-amd64-legacy` / `.tar.gz` | Debian 12، Ubuntu 22.04 و Rocky Linux 9 (خطای `GLIBC_2.38` not found) |
   | `madmail-linux-amd64-musl` / `.tar.gz` | جایگزین musl |
   | معادل‌های arm64 (`…-arm64…`، `…-legacy…`، `…-musl…`) | همین شرایط برای arm64 |
   | `madmail-windows-amd64-setup.exe` | Windows 10 و 11 (x64). Iroh روی Windows در دسترس نیست. نصاب پایدار در حال حاضر فاقد پنل وب مدیریت است؛ نصاب‌های پیش‌انتشار `Madmail TESTING` متفاوت هستند ([جزئیات](../../guide/install.md#supported-operating-systems)) |

   مثال با `wget` (amd64 پیش‌فرض):

   ```bash
   wget https://github.com/themadorg/madmail/releases/download/vX.Y.Z/madmail-linux-amd64
   chmod +x madmail-linux-amd64
   sudo mv madmail-linux-amd64 /usr/local/bin/madmail
   ```

   باینری‌های موجود در انتشار‌های رسمی همان‌هایی هستند که توسط این پروژه تولید می‌شوند. نگارشی را انتخاب کنید که روی هاست شما اجرا می‌شود و **همان نگارش را برای به‌روزرسانی‌های بعدی نیز حفظ کنید**.

## ارتقای امن با `madmail upgrade`

پس از نصب `madmail`، به‌روزرسانی‌های بعدی را می‌توان به‌صورت امن با دستور داخلی upgrade انجام داد:

```bash
# Use the same variant you installed (default / legacy / musl)
sudo madmail upgrade https://github.com/themadorg/madmail/releases/latest/download/madmail-linux-amd64.tar.gz
# older glibc hosts:
# sudo madmail upgrade https://github.com/themadorg/madmail/releases/latest/download/madmail-linux-amd64-legacy.tar.gz
```

### نحوه کارکرد

- اگر یک فایل محلی یا نشانی اینترنتی (URL) دانلود به آن بدهید، `madmail upgrade`:
  1. باینری جدید را دانلود می‌کند (در صورتی که URL ارائه شده باشد).
  2. اگر URL مربوط به آرشیو انتشار `.tar.gz` / `.tgz` باشد، ابتدا باینری را استخراج می‌کند.
  3. **امضای دیجیتال** (Ed25519) را که به باینری انتشار پیوست شده است **اعتبارسنجی می‌کند**.
  4. اگر امضا نامعتبر باشد یا وجود نداشته باشد، ارتقا **لغو می‌شود** — باینری هرگز نصب نمی‌شود. این کار از سرور در برابر انتشارهای دستکاری‌شده یا به خطر افتاده محافظت می‌کند.
  5. **بررسی اولیه هاست (Host preflight):** باینری جدید را اجرا می‌کند (`version`) قبل از اینکه به نسخه فعال دست بزند. عدم تطابق نگارش یا glibc به شکل امنی فرایند را متوقف می‌کند (سرویس بالا می‌ماند).
  6. از باینری فعلی در کنار مسیر نصب یک کپی با نام `madmail.prev` می‌گیرد.
  7. سرویس `madmail.service` (و iroh-relay در صورت وجود) را متوقف می‌کند.
  8. باینری در حال اجرا را به‌صورت اتمیک جایگزین می‌کند؛ در صورت خرابی در تست اولیه پس از نصب (smoke test)، فایل `*.prev` را بازیابی کرده و مجدداً راه‌اندازی می‌کند.
  9. ممکن است برای تبدیل قالب‌های سفارشی Go در `www_dir` به Minijinja و اصلاح QRهای قدیمی `/qr?data=` پیام تایید نمایش دهد (`html-migrate`).
  10. سرویس(ها) را مجدداً راه‌اندازی می‌کند.

این روش، شیوه پشتیبانی‌شده برای به‌روزرسانی سرور عملیاتی همراه با اعتبارسنجی امضا است.

همان باینری‌های امضاشده و فایل‌های `.tar.gz` از https://github.com/themadorg/madmail/releases را می‌توان با `madmail upgrade` استفاده کرد.

## گزینه ۱: سرور عمومی روی IP واقعی

این مسیر یک راه‌اندازی کامل عملیاتی (سرویس systemd، کاربر، پوشه‌ها و گواهی) را نصب می‌کند.

راهنمای کوتاه اختصاصی آن را ببینید:

**[نصب روی IP عمومی با Let’s Encrypt](../../install-simple-ip-acme.md)**

خلاصه آن به این صورت است (اجرا به عنوان root):

```bash
madmail install --simple --ip YOUR.PUBLIC.IP.ADDRESS \
  --auto-ip-cert \
  --acme-email you@yourdomain.com
```

این دستور:
- کاربر سیستمی و پوشه‌ها را ایجاد می‌کند
- یک توکن مدیریت قوی تولید می‌کند
- یک گواهی مورد اعتماد مرورگر دریافت می‌کند (حتی اگر فقط یک IP داشته باشید و نام DNS نداشته باشید)
- یک پیکربندی پایه می‌نویسد
- سرویس systemd را پیکربندی می‌کند

پس از نصب، دستور `sudo systemctl enable --now madmail` را اجرا کنید. به محض اینکه سرویس در حال اجرا باشد و فایروال اجازه دسترسی بدهد، سرور شما روی پورت‌های معمولی ایمیل قابل دسترسی خواهد بود و می‌توانید با استفاده از آدرس IP خود یا دامنه‌ای که به آن اشاره دارد، با دلتاچت متصل شوید.

## گزینه ۲: استفاده از رابط وب مدیریت

در نصب‌های معمولی و نسخه‌های انتشار رسمی، رابط وب مدیریت از قبل در باینری `madmail` گنجانده شده است.

پس از اینکه سرور در حال اجرا داشتید:

1. آدرس `https://your-server/admin/` (یا مسیری که پیکربندی کرده‌اید) را باز کنید.

2. با استفاده از توکن موجود در فایل `admin_token` (یا توکنی که حین اجرای `madmail install` نمایش داده شد) وارد شوید.

می‌توانید رابط وب مدیریت را با استفاده از دستورات CLI فعال، غیرفعال یا مسیر آن را تغییر دهید (به [راهنمای مدیریت و CLI](./07-admin-and-cli.md) مراجعه کنید).

از طریق رابط وب می‌توانید:
- ثبت‌نام را باز کرده یا ببندید
- توکن‌های ثبت‌نام ایجاد کنید (برای حالت فقط با دعوت)
- کاربران را مسدود (ban) کنید
- وضعیت سلامت فدراسیون را مشاهده کنید
- سهمیه‌ها و محدودیت‌ها را تغییر دهید
- بدون تایپ دستورات، سرور را مدیریت کنید

## نخستین کارهایی که اغلب مدیران سرور انجام می‌دهند

پس از اینکه سرور شروع به کار کرد:

1. تصمیم بگیرید که آیا کاربران جدید می‌توانند آزادانه ثبت‌نام کنند یا خیر (`registration open` یا بسته).
2. اگر می‌خواهید مقداری کنترل داشته باشید، چند توکن ثبت‌نام ایجاد کنید.
3. یک سهمیه ذخیره‌سازی پیش‌فرض و منطقی تعیین کنید.
4. مطمئن شوید که یک استراتژی پشتیبان‌گیری برای `state_dir` (پایگاه‌داده + پوشه `mail/`) دارید.
5. (اختیاری اما مناسب) یک نام دامنه را به سرور متصل کرده و پیکربندی را به‌روزرسانی کنید.

## محل ذخیره‌سازی داده‌های سرور (مکان‌های پیش‌فرض)

به‌طور پیش‌فرض، تقریباً همه‌چیز در یک **پوشه وضعیت** واحد قرار می‌گیرد. این ویژگی، پشتیبان‌گیری و مدیریت را ساده می‌کند.

### پوشه وضعیت پیش‌فرض

- **روی سرورهای محیط عملیاتی (production)**: `/var/lib/madmail`
- **نصب‌های قدیمی** (راه‌اندازی‌های قبلی madmail/maddy): `/var/lib/maddy`
- **توسعه/آزمایش محلی**: `./data` (نسبت به محلی که باینری را اجرا می‌کنید)

می‌توانید این مقدار را با `--state-dir` در خط فرمان یا تنظیم `state_dir` در فایل پیکربندی بازنویسی کنید.

### ساختار پوشه درون پوشه وضعیت

```
state_dir/
├── admin_token                  # 64-character admin API token (file permissions 0600)
├── chatmail.db                  # Main SQLite database when using the default driver (settings, accounts, quotas, …)
├── credentials.db               # Legacy / install default SQLite file (`auth.pass_table` `dsn`)
├── mail/                        # All user mailboxes in Maildir format
│   ├── alice@example.com/
│   │   └── Maildir/
│   │       ├── cur/             # Messages with flags
│   │       ├── new/             # Newly delivered messages
│   │       └── tmp/
│   └── bob@example.com/
│       └── folders/
│           └── DeltaChat/
│               └── Maildir/     # Most Delta Chat history lives here
├── remote_queue/                # Persistent storage for the outbound delivery retry queue
├── certs/                       # TLS certificates and keys (when using file-based TLS)
│   ├── fullchain.pem
│   └── privkey.pem
└── autocert/                    # Let's Encrypt / ACME account keys and state
```

### سایر مکان‌های مهم (خارج از پوشه وضعیت)

- **پیکربندی اصلی**: معمولاً `/etc/madmail/madmail.conf` (یا `chatmail.toml`)
- **لاگ‌ها**: معمولاً با `journalctl -u madmail` (در systemd) مشاهده می‌شوند. برخی راه‌اندازی‌ها در فایل نیز لاگ ثبت می‌کنند.
- **واحد systemd**: واحد `madmail.service`

### چرا این چیدمان؟

- یک پوشه واحد (`state_dir`) برای پشتیبان‌گیری، پایگاه‌داده + ایمیل همه کاربران را در اختیارتان می‌گذارد.
- ذخیره‌سازی ایمیل از ساختار استاندارد Maildir استفاده می‌کند، بنابراین بررسی، مهاجرت یا عیب‌یابی آن با ابزارهای معمولی Unix ساده است.
- دلتاچت بخش عمده تاریخچه چت را درون پوشه `folders/DeltaChat/Maildir/` هر کاربر ذخیره می‌کند.
- توکن مدیریت به دلایل امنیتی در قالب یک فایل مجزا (هرگز درون پایگاه‌داده ذخیره نمی‌شود) قرار می‌گیرد.

### پشتیبان‌ها

ساده‌ترین پشتیبان قابل اطمینان، تهیه یک snapshot یا کپی از کل `state_dir` است (در حالت ایده‌آل زمانی که سرویس متوقف شده باشد، یا با استفاده از ابزارهای مناسبی که فایل‌های WAL در SQLite را به درستی مدیریت می‌کنند). اگر پایگاه‌داده برنامه **PostgreSQL** است، از آن به‌طور جداگانه پشتیبان تهیه کنید — به [PostgreSQL به عنوان پایگاه‌داده برنامه](./18-postgres.md) مراجعه کنید. دستور `madmail install` همیشه SQLite را می‌نویسد. برای کپی کردن پایگاه‌داده برنامه موجود از SQLite به Postgres، از `madmail db sqlite-to-postgres` استفاده کنید (همان راهنما).

## ارائه باینری و مستندات توسط خود سرور

هر سرور چتمیل می‌تواند فایل باینری فعلی خود را روی مسیر `/madmail` ارائه دهد:

```
https://your-server.example.com/madmail
```

این ویژگی برای راه‌اندازی سرورهای دیگر بسیار مفید است.

**شیوه پیشنهادی:**

- برای **نخستین** سرور خود، باینری را از بخش انتشارات رسمی در GitHub دریافت کنید (https://github.com/themadorg/madmail/releases). این کار یک نقطه شروع مطمئن و امضاشده به شما می‌دهد.

- پس از اینکه دست‌کم یک سرور قابل اعتماد در حال اجرا داشتید، می‌توانید باینری‌ها را با استفاده از مسیر `/madmail` از سایر سرورهای چتمیل دانلود کنید. این کار امن است زیرا انتشارات رسمی به‌صورت دیجیتالی امضا شده‌اند. هنگامی که بعداً `madmail upgrade` را با یک باینری از سروری دیگر (یا یک URL) اجرا کنید، قبل از نصب امضا را اعتبارسنجی می‌کند.

همچنین هر سرور مجموعه کاملی از مستندات را مستقیماً در مسیر زیر ارائه می‌دهد:

```
https://your-server.example.com/docs/
```

این شامل راهنماهای چندزبانه برای کاربران و مدیران سرور است. این مستندات همواره از خود سرور، حتی در محیط‌های شبکه‌ای دارای محدودیت، در دسترس هستند.

## دانلود باینری به‌طور مستقیم از هر سرور

هر سرور چتمیل می‌تواند فایل باینری خود را در مسیر `/madmail` ارائه دهد.

مثال:

```
https://your-server.example.com/madmail
```

این کار می‌تواند راه‌اندازی اولیه یا به‌روزرسانی سایر سرورها را ساده‌تر کند.

**بهترین روش برای نصب اولیه:**

برای نخستین سروری که راه‌اندازی می‌کنید، توصیه می‌شود باینری را از بخش انتشارهای رسمی در GitHub دانلود کنید:

→ https://github.com/themadorg/madmail/releases

این کار اطمینان می‌دهد که کار را با یک انتشار معتبر، مطمئن و به‌درستی امضاشده آغاز می‌کنید.

**پس از اجرای نخستین سرور:**

می‌توانید باینری را از هر سرور چتمیل معتمد دیگری (از جمله سرور خودتان) با استفاده از مسیر `/madmail` دانلود کنید.

این روش بر **امضای دیجیتال باینری‌های رسمی** تکیه دارد. وقتی بعداً دستور زیر را اجرا می‌کنید:

```bash
madmail upgrade /path/to/downloaded/binary
# or
madmail upgrade https://another-server.com/madmail
```

دستور `madmail upgrade` امضا را پیش از نصب باینری جدید تأیید می‌کند. اگر امضا نامعتبر باشد یا وجود نداشته باشد، ارتقا لغو خواهد شد.

این به شما امکان می‌دهد تا زمانی که دست‌کم یک نقطه شروع معتمد دارید، حتی در محیط‌های محدود نیز کل شبکه‌ای از سرورها را راه‌اندازی اولیه کنید.

## چندین آدرس روی یک سرور

پس از نصب، آدرس‌های سرور را در `/etc/madmail/madmail.conf` تنظیم کنید:

```conf
$(primary_domain) = b.com c.com 1.1.1.1
$(local_domains) = $(primary_domain)
```

مقدار `jit_domain $(primary_domain)` را در `auth.pass_table` نگه دارید، یا `jit_domain` را حذف کنید تا از کل فهرست دامنه‌های اصلی استفاده شود. پس از ویرایش، سرویس را راه‌اندازی مجدد کنید. هر دو نام DNS را به سمت سرور هدایت کنید و گواهی‌های TLS پوشش‌دهنده آدرس‌های استفاده‌شده را ارائه دهید. باز کردن هر آدرس، حساب‌هایی با همان دامنه ایمیل ایجاد می‌کند؛ حساب‌های IPv4 از براکت استفاده می‌کنند، به عنوان مثال `user@[1.1.1.1]`. هر آدرس ایمیل کامل، صندوق پستی اختصاصی خود را دارد. اگر نام میزبانِ درخواست مرورگر در فهرست نباشد، دامنهٔ اول پیش‌فرض است و هویت اصلی (canonical) سرور می‌ماند.

### متوقف کردن ثبت‌نام JIT روی دامنه‌های انتخابی

همه آدرس‌ها را در فهرست دامنه‌های سرور نگه دارید تا حساب‌های موجود همچنان ایمیل دریافت کنند، و `jit_domain` را به دامنه‌هایی محدود کنید که مجاز به ایجاد حساب‌های جدید هستند:

```conf
$(primary_domain) = b.com c.com 1.1.1.1
auth.pass_table local_authdb {
    auto_create yes
    jit_domain c.com
    table sql_table {
        driver sqlite3
        dsn credentials.db
        table_name passwords
    }
}
```

پس از راه‌اندازی مجدد سرویس، حساب‌های جدید JIT فقط می‌توانند از `@c.com` استفاده کنند. حساب‌های موجود در `@b.com` و `@[1.1.1.1]` همچنان با رمزهای عبور فعلی خود وارد می‌شوند. چند دامنه مجاز JIT را می‌توان با فاصله یا کاما از هم جدا کرد. تا زمانی که حساب‌های یک دامنه کنار گذاشته‌شده هنوز نیاز به دریافت ایمیل دارند، آن دامنه را از فهرست دامنه‌های محلی سرور حذف نکنید.

پارامتر `jit_domain` ایجاد حساب هنگام اولین ورود را از طریق IMAP/SMTP کنترل می‌کند. ثبت‌نام عمومی `/new` سیاست ثبت‌نام/توکن مخصوص به خود را دارد؛ محدود کردن `jit_domain` آن نقطه پایانی را غیرفعال نمی‌کند. ایجاد صریح حساب از طریق CLI یک عملیات مدیریتی است و روی دامنه‌های بازنشسته‌شده JIT همچنان در دسترس باقی می‌ماند.

برای یک دستورالعمل کامل مدیریت دامنه، شامل بازنشستگی انتخابی JIT و ایجاد حساب از طریق CLI، به [انگلیسی](../../guide/recipes/server-domains_en.md) / [فارسی](../../guide/recipes/server-domains_fa.md) مراجعه کنید.
