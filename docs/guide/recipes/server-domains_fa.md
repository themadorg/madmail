# چند آدرس سرور و ثبت‌نام انتخابی JIT

[English](server-domains_en.md)

هنگامی از این دستورالعمل استفاده کنید که یک سرور Madmail چندین نام DNS یا آدرس IP دارد و می‌خواهید مشخص کنید کدام دامنه‌ها همچنان ایجاد حساب‌های جدید را از طریق ساخت خودکار حساب هنگام اولین ورود (JIT) مجاز می‌دانند.

## میزبانی چندین آدرس از یک سرور

پس از نصب، فایل `/etc/madmail/madmail.conf` را ویرایش کنید:

```conf
$(primary_domain) = b.com c.com 1.1.1.1
$(local_domains) = $(primary_domain)
```

فهرست primary-domain فاصله یا کاما را می‌پذیرد. اولین ورودی، هویت اصلی سرور و دامنه پیش‌فرض حساب است. هر ورودی در این فهرست برای تحویل محلی پذیرفته می‌شود؛ ورودی‌های اضافی `local_domains` نیز پشتیبانی می‌شوند.

نام‌های DNS را به همین سرور متصل کنید و گواهی‌های TLS را به‌گونه‌ای پیکربندی نمایید که آدرس‌های مورد استفاده کلاینت‌ها را پوشش دهند. صرف درج دامنه‌ها در فهرست، DNS را پیکربندی نمی‌کند و گواهی‌ها را به‌طور خودکار برای همه آن‌ها دریافت نخواهد کرد.

| آدرس بازشده در مرورگر | دامنه حساب |
|---|---|
| `https://b.com` | `user@b.com` |
| `https://c.com` | `user@c.com` |
| `https://1.1.1.1` | `user@[1.1.1.1]` |

صفحه ثبت‌نام و اندپوینت عمومی `POST /new` تنها زمانی یک hostname مرورگر را انتخاب می‌کنند که با یک دامنه محلی پذیرفته‌شده مطابقت داشته باشد. در فرآیند تطبیق، بزرگی و کوچکی حروف نام DNS نادیده گرفته شده و پورت حذف می‌شود. یک hostname ناشناخته یا ناقص به عنوان حالت بازگشتی به اولین دامنه اصلی رجوع می‌کند.

هر آدرس ایمیل کامل، یک حساب کاربری جداگانه با صندوق پستی و اطلاعات اعتبارسنجی مستقل خود است. `a@b.com`، `a@c.com` و `a@[1.1.1.1]` به‌طور خودکار نام مستعار یکدیگر نیستند. دامنه‌های ایمیل مبتنی بر IPv4 از براکت استفاده می‌کنند، هرچند که در ورود و ورودی CLI می‌توان از یک آدرس IPv4 بدون براکت استفاده کرد و سیستم آن را نرمال‌سازی می‌کند.

## مجاز کردن ثبت‌نام JIT در تمام دامنه‌های فهرست‌شده

سازوکار JIT زمانی حسابی را ایجاد می‌کند که یک کلاینت برای نخستین‌بار با یک نام کاربری ناشناخته از طریق IMAP یا SMTP وارد شود و خط‌مشی ثبت‌نام اجازه ایجاد آن را بدهد.

در بلوک موجود `auth.pass_table`، از این مقدار استفاده کنید:

```conf
jit_domain $(primary_domain)
```

هنگامی که `jit_domain` حذف شود، مقدار پیش‌فرض آن به کل فهرست primary-domain تنظیم می‌شود. یک تنظیم صریح جایگزین آن فهرست مجاز پیش‌فرض می‌شود. این تنظیم می‌تواند شامل چند دامنه باشد که با فاصله یا کاما از هم جدا شده‌اند:

```conf
jit_domain b.com c.com
```

## کنار گذاشتن یک دامنه از JIT بدون قطع دسترسی حساب‌های موجود

همه آدرس‌ها را در فهرست دامنه‌های سرور نگه دارید و دامنه `jit_domain` را محدودتر کنید. برای نمونه، این بلوک احراز هویت حساب‌های JIT جدید را تنها در `c.com` مجاز می‌داند:

```conf
$(primary_domain) = b.com c.com 1.1.1.1
$(local_domains) = $(primary_domain)

auth.pass_table local_authdb {
    auto_create yes
    jit_domain c.com
    table sql_table {
        driver sqlite3
        dsn credentials.db
        table_name passwords
    }
}
```

به‌جای جایگزین کردن کل فایل، پیکربندی موجود را تطبیق دهید. درایور پایگاه داده، DSN، تنظیمات ذخیره‌سازی، شنونده‌ها و تنظیمات TLS فعلی خود را حفظ کنید. پس از تغییر پیکربندی ایستا، سرور در حال اجرا را مجدداً راه‌اندازی کنید. در سامانه‌های مبتنی بر systemd:

```bash
sudo systemctl restart madmail
```

| تلاش برای ورود | نتیجه در صورت فعال بودن JIT و تنظیم `jit_domain c.com` |
|---|---|
| حساب موجود در `b.com` با گذرواژه درست | ورود موفقیت‌آمیز است |
| حساب موجود در `c.com` با گذرواژه درست | ورود موفقیت‌آمیز است |
| حساب موجود در `[1.1.1.1]` با گذرواژه درست | ورود موفقیت‌آمیز است |
| حساب ناشناخته در `c.com` | در صورتی که سایر خط‌مشی‌های ثبت‌نام اجازه دهند ممکن است ایجاد شود |
| حساب ناشناخته در `b.com` یا `[1.1.1.1]` | ایجاد از طریق JIT رد می‌شود |
| حساب موجود با گذرواژه نادرست | ورود رد می‌شود |

حساب‌های مسدودشده یا حذف‌شده قبلی همچنان مشمول محدودیت‌های عادی حساب کاربری خود خواهند بود. محدود کردن JIT گذرواژه‌ها را تغییر نمی‌دهد و صندوق‌های پستی را ادغام نمی‌کند. تا زمانی که حساب‌های یک آدرس کنار گذاشته شده همچنان نیاز به دریافت ایمیل دارند، آن آدرس را از دامنه‌های محلی پذیرفته‌شده حذف نکنید.

## تفکیک JIT، ثبت‌نام عمومی و ایجاد توسط مدیر

تنظیم `jit_domain` صرفاً **ایجاد حساب در اولین ورود از طریق IMAP/SMTP** را محدود می‌کند. این تنظیم ثبت‌نام عمومی از طریق `/new` را در آن دامنه‌ها غیرفعال نمی‌کند. آن اندپوینت، خط‌مشی‌های باز بودن ثبت‌نام و توکن ثبت‌نام مخصوص به خود را دارد. صفحه مرورگر همچنین ممکن است اطلاعات ورود را به‌صورت محلی برای ورود بعدی از طریق JIT تولید کند؛ اطلاعات ورود مربوط به دامنه‌ای که از JIT کنار گذاشته شده است، در ایجاد حساب جدید از این مسیر ناموفق خواهد بود.

اگر هدف شما مسدود کردن تمام مسیرهای ایجاد عمومی روی یک دامنه است، تنها محدود کردن JIT کافی نیست. به [کنترل‌های ثبت‌نام](../cli/registration.md) و [کنترل‌های توکن ثبت‌نام](../cli/registration-tokens.md) مراجعه کنید.

ایجاد صریح حساب از طریق CLI یک عملیات مدیریتی است و فهرست مجاز دامنه‌های JIT را نادیده می‌گیرد. این قابلیت به مدیر سیستم اجازه می‌دهد تا حتی در دامنه‌ای که از JIT کنار گذاشته شده است، حساب‌ها را به‌صورت عمدی ایجاد کند.

## ایجاد حساب‌ها با CLI

برای انتخاب دامنه از یک آدرس کامل استفاده کنید. در صورت حذف `--password`، گذرواژه از شما درخواست می‌شود:

```bash
madmail accounts create a@b.com
madmail accounts create a@c.com
madmail accounts create 'a@[1.1.1.1]'
```

این دستورها سه حساب جداگانه ایجاد می‌کنند. به‌جز نرمال‌سازی نام کاربری، آدرس کامل حفظ می‌شود؛ دامنه‌های IPv4 بدون براکت، داخل براکت قرار می‌گیرند:

```bash
madmail accounts create a@1.1.1.1
```

یک نام کاربری بدون `@` از اولین primary domain استفاده می‌کند:

```bash
madmail accounts create a
```

با پیکربندی فوق، این دستور `a@b.com` را ایجاد می‌کند. دستور `madmail accounts create-random` و نام مستعار آن یعنی `madmail create-user` نیز از اولین primary domain استفاده می‌کنند. برای انتخاب دامنه‌ای متفاوت، از دستور صریح `accounts create user@domain` استفاده کنید. اگر قرار است حساب مورد نظر روی این سرور ایمیل دریافت کند، آن دامنه را در فهرست پذیرفته‌شده محلی نگه دارید.

جزئیات بیشتر درباره CLI: [accounts create](../cli/accounts-create.md) و [accounts create-random](../cli/accounts-create-random.md).

## عیب‌یابی

- شکست در ورود جدید روی دامنه کنار گذاشته شده: بررسی کنید که آیا آدرس ایمیل کامل در پایگاه داده اطلاعات ورود پیکربندی‌شده وجود دارد یا خیر. یک حساب ناشناخته مشمول محدودیت‌های JIT است.
- شکست در ورود حساب موجود: آدرس کامل، گذرواژه، لیست مسدودشده‌ها، نسخه سرور در حال اجرا و پایگاه داده اطلاعات ورود انتخاب‌شده در پیکربندی را بررسی کنید.
- حساب تحت دامنه اشتباه ایجاد می‌شود: نام میزبان مرورگر، دامنه‌های محلی پذیرفته‌شده و ترتیب فهرست primary-domain را بررسی کنید.
- رخ دادن خطای TLS یا اتصال قبل از ورود: وضعیت DNS، پوشش گواهی، پورت‌های شنونده و دسترسی‌پذیری شبکه را مستقل از خط‌مشی JIT بررسی کنید.

این رفتار توسط آزمون‌های پیکربندی/احراز هویت، بررسی‌های ورود و ثبت‌نام چنددامنه‌ای داکر و آزمون رگرسیون سرتاسری کنار گذاشتن دامنه از طریق CLI/JIT پوشش داده شده است.

## DKIM برای چند دامنه

ایمیل خروجی از هر نام DNS در `primary_domain` با همان دامنهٔ آدرس `From`
امضا می‌شود. آدرس‌های IP امضا نمی‌شوند، اما اگر اولین ورودی IP باشد، امضای
دامنه‌های DNS بعدی همچنان فعال است. `local_domains` و `jit_domain` دامنه‌ای
به فهرست دامنه‌های مجاز برای امضا اضافه نمی‌کنند.

با اجرای `madmail dkim show`، رکورد TXT نمایش‌داده‌شده را برای هر دامنهٔ اصلی DNS
در `default._domainkey.<domain>` منتشر کنید. همهٔ این دامنه‌ها از همان selector
و کلید خصوصی موجود استفاده می‌کنند. دستورهای `madmail dkim check` و
`madmail dkim status` هر دامنهٔ اصلی را گزارش می‌کنند. خروجی JSON برای چند
دامنه، آرایهٔ `domains` را اضافه می‌کند و فیلدهای قبلی دامنهٔ اول را نگه می‌دارد.

حساب‌های IPv6 شکل بدون براکت موجود (`user@2001:db8::1`) را حفظ می‌کنند.
نام میزبان مرورگر و آدرس ورود دارای براکت به همین شکل تبدیل می‌شوند؛ بنابراین
صفحه، `/new` و ورود از یک شکل آدرس استفاده می‌کنند.
