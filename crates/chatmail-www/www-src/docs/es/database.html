Configuración de la base de datos

Madmail guarda cuentas, ajustes, cuotas, tokens y el estado de federación en una base SQL de aplicación: SQLite (predeterminada) o PostgreSQL. Los cuerpos de los mensajes siguen en disco (Maildir). Las páginas de compartir contactos usan otro SQLite (sharing.db).

MySQL no está soportado. Cambiar driver no copia un SQLite existente. Después de editar driver / dsn, reinicie el proceso: madmail reload no vuelve a abrir la base.

SQLite (predeterminado)

madmail install siempre escribe driver sqlite3. La ruta sigue su state_dir.

auth.pass_table local_authdb {
    table sql_table {
        driver sqlite3
        dsn /var/lib/madmail/credentials.db
        table_name passwords
    }
}

PostgreSQL (base vacía)

Cree una base vacía y un rol que pueda crear tablas. Ponga el mismo driver postgres y DSN en ambos bloques auth.pass_table y storage.imapsql (v2 abre el DSN de auth; mantenerlos iguales evita una config engañosa).

CREATE USER madmail WITH PASSWORD 'choose-a-secret';
CREATE DATABASE madmail OWNER madmail;

Ejemplo en madmail.conf:

auth.pass_table local_authdb {
    auto_create yes
    jit_domain $(primary_domain)
    table sql_table {
        driver postgres
        dsn host=127.0.0.1 port=5432 user=madmail password=choose-a-secret dbname=madmail sslmode=disable
        table_name passwords
    }
}

storage.imapsql local_mailboxes {
    auto_create yes
    driver postgres
    dsn host=127.0.0.1 port=5432 user=madmail password=choose-a-secret dbname=madmail sslmode=disable
    retention 24h
    default_quota 1G
    appendlimit 100M
}

También vale la forma URL: postgres://madmail:choose-a-secret@127.0.0.1:5432/madmail?sslmode=disable.

Luego reinicie Madmail. El primer arranque contra Postgres vacío aplica migraciones sqlx. No use GORM ni cree a mano las tablas quotas / contacts.

Copiar SQLite → PostgreSQL

Pare el servidor para que SQLite esté quieto y luego:

madmail db sqlite-to-postgres --dsn 'host=127.0.0.1 user=madmail dbname=madmail sslmode=disable' --dry-run
madmail db sqlite-to-postgres --dsn 'host=127.0.0.1 user=madmail dbname=madmail sslmode=disable' -y

Después de copiar, ponga driver postgres como arriba y arranque el servidor. Solo copia tablas de aplicación. No mueve Maildir, la cola de reintentos, admin_token ni sharing.db, y no reescribe madmail.conf. Si Postgres ya tiene filas de contraseñas, use --force.

Cachés en memoria frente al estado en disco

Por rendimiento, el servidor en ejecución puede mantener en RAM una copia de las filas de credenciales (auth.pass_table) y los totales de cuota por usuario (storage.imapsql). Los datos autoritativos siguen en la base.

Si modifica esas bases con la CLI (por ejemplo madmail creds, madmail accounts o madmail imap-acct) mientras el demonio sigue en marcha, invoque una vez el recurso de la API de administración POST /admin/cache/reload para que el proceso vuelva a leer las tablas. También puede reiniciar el servicio.
