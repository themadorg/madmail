Настройка базы данных

Madmail хранит учётные записи, настройки, квоты, токены и состояние федерации в одной прикладной SQL-базе: SQLite (по умолчанию) или PostgreSQL. Тела писем остаются на диске (Maildir). Страницы обмена контактами используют отдельный SQLite-файл (sharing.db).

MySQL не поддерживается. Смена driver сама по себе не копирует существующий SQLite. После правки driver / dsn процесс нужно перезапустить — madmail reload базу заново не открывает.

SQLite (по умолчанию)

madmail install всегда пишет driver sqlite3. Путь к файлу следует за вашим state_dir.

auth.pass_table local_authdb {
    table sql_table {
        driver sqlite3
        dsn /var/lib/madmail/credentials.db
        table_name passwords
    }
}

PostgreSQL (пустая база)

Создайте пустую базу и роль, которая может создавать таблицы. Укажите один и тот же driver postgres и DSN в обоих блоках auth.pass_table и storage.imapsql (v2 открывает DSN из auth; расхождение только путает конфиг).

CREATE USER madmail WITH PASSWORD 'choose-a-secret';
CREATE DATABASE madmail OWNER madmail;

Пример в madmail.conf:

auth.pass_table local_authdb {
    auto_create yes
    jit_domain $(primary_domain)
    table sql_table {
        driver postgres
        dsn host=127.0.0.1 port=5432 user=madmail password=choose-a-secret dbname=madmail sslmode=disable
        table_name passwords
    }
}

storage.imapsql local_mailboxes {
    auto_create yes
    driver postgres
    dsn host=127.0.0.1 port=5432 user=madmail password=choose-a-secret dbname=madmail sslmode=disable
    retention 24h
    default_quota 1G
    appendlimit 100M
}

URL тоже принимается: postgres://madmail:choose-a-secret@127.0.0.1:5432/madmail?sslmode=disable.

Затем перезапустите Madmail. Первый старт на пустом Postgres применяет миграции sqlx. GORM не используется; таблицы quotas / contacts вручную создавать не нужно.

Копирование SQLite → PostgreSQL

Остановите сервер, чтобы SQLite был свободен, затем:

madmail db sqlite-to-postgres --dsn 'host=127.0.0.1 user=madmail dbname=madmail sslmode=disable' --dry-run
madmail db sqlite-to-postgres --dsn 'host=127.0.0.1 user=madmail dbname=madmail sslmode=disable' -y

После копирования задайте driver postgres как выше и запустите сервер. Копируются только прикладные таблицы. Maildir, очередь повторов, admin_token и sharing.db не переносятся, madmail.conf не переписывается. Если в Postgres уже есть строки паролей, нужен --force.

Кэши в памяти и данные на диске

Для производительности сервер может хранить в RAM копию строк учётных данных (auth.pass_table) и агрегаты квот (storage.imapsql). Источник истины — база данных.

Если вы меняете БД через CLI (madmail creds, madmail accounts, madmail imap-acct и т.д.) при работающем демоне, один раз вызовите Admin API POST /admin/cache/reload, чтобы процесс перечитал таблицы, либо перезапустите сервис.
