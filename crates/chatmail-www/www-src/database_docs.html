Database Configuration

Madmail stores accounts, settings, quotas, tokens, and federation state in one application SQL database: SQLite (default) or PostgreSQL. Mail bodies stay on disk as Maildir. Contact-sharing pages use a separate SQLite file (sharing.db).

MySQL is not supported. Changing driver does not copy an existing SQLite file by itself. After you edit driver / dsn, restart the process — madmail reload does not re-open the database.

SQLite (default)

madmail install always writes driver sqlite3. The file path follows your state_dir.

auth.pass_table local_authdb {
    table sql_table {
        driver sqlite3
        dsn /var/lib/madmail/credentials.db
        table_name passwords
    }
}

PostgreSQL (empty database)

Create an empty database and a role that can create tables. Set both auth.pass_table and storage.imapsql to the same Postgres driver and DSN.

CREATE USER madmail WITH PASSWORD 'choose-a-secret';
CREATE DATABASE madmail OWNER madmail;

Example in madmail.conf:

auth.pass_table local_authdb {
    auto_create yes
    jit_domain $(primary_domain)
    table sql_table {
        driver postgres
        dsn host=127.0.0.1 port=5432 user=madmail password=choose-a-secret dbname=madmail sslmode=disable
        table_name passwords
    }
}

storage.imapsql local_mailboxes {
    auto_create yes
    driver postgres
    dsn host=127.0.0.1 port=5432 user=madmail password=choose-a-secret dbname=madmail sslmode=disable
    retention 24h
    default_quota 1G
    appendlimit 100M
}

URL form is also accepted: postgres://madmail:choose-a-secret@127.0.0.1:5432/madmail?sslmode=disable.

Then restart Madmail. First start against empty Postgres applies sqlx migrations.

Copy SQLite → PostgreSQL

madmail db sqlite-to-postgres --dsn 'host=127.0.0.1 user=madmail dbname=madmail sslmode=disable' --dry-run
madmail db sqlite-to-postgres --dsn 'host=127.0.0.1 user=madmail dbname=madmail sslmode=disable' -y

Stop the server first. This copies application tables only — not Maildir, admin_token, or sharing.db. Then set driver postgres and start the server. Use --force if Postgres already has password rows.

In-memory caches vs on-disk state

For performance, the running server may keep a copy of credential rows (auth.pass_table) and per-user quota totals (storage.imapsql) in RAM. The authoritative data remains in the database.

If you change those databases with the CLI (for example madmail creds, madmail accounts, or madmail imap-acct) while the daemon stays up, call the Admin API resource POST /admin/cache/reload once so the process re-reads the tables. Alternatively, restart the service.

Configuración de la base de datos

Madmail guarda cuentas, ajustes, cuotas, tokens y el estado de federación en una base SQL: SQLite (predeterminada) o PostgreSQL. El correo sigue en Maildir. Las páginas de compartir contactos usan sharing.db (siempre SQLite).

MySQL no está soportado. Cambiar driver no copia un SQLite existente. Después de editar driver / dsn, reinicie el proceso: madmail reload no vuelve a abrir la base.

SQLite (predeterminado)

madmail install siempre escribe driver sqlite3.

auth.pass_table local_authdb {
    table sql_table {
        driver sqlite3
        dsn /var/lib/madmail/credentials.db
        table_name passwords
    }
}

PostgreSQL (base vacía)

Cree una base vacía. Ponga el mismo DSN en auth.pass_table y storage.imapsql, luego reinicie.

CREATE USER madmail WITH PASSWORD 'choose-a-secret';
CREATE DATABASE madmail OWNER madmail;
auth.pass_table local_authdb {
    auto_create yes
    jit_domain $(primary_domain)
    table sql_table {
        driver postgres
        dsn host=127.0.0.1 port=5432 user=madmail password=choose-a-secret dbname=madmail sslmode=disable
        table_name passwords
    }
}

storage.imapsql local_mailboxes {
    auto_create yes
    driver postgres
    dsn host=127.0.0.1 port=5432 user=madmail password=choose-a-secret dbname=madmail sslmode=disable
    retention 24h
    default_quota 1G
    appendlimit 100M
}

Copiar SQLite → PostgreSQL

madmail db sqlite-to-postgres --dsn 'host=127.0.0.1 user=madmail dbname=madmail sslmode=disable' --dry-run
madmail db sqlite-to-postgres --dsn 'host=127.0.0.1 user=madmail dbname=madmail sslmode=disable' -y

Pare el servidor primero. Solo copia tablas de aplicación. Luego ponga driver postgres y arranque. Use --force si Postgres ya tiene filas de contraseñas.

Cachés en memoria frente al estado en disco

El servidor puede mantener en RAM una copia de credenciales y cuotas. Si cambia la base con la CLI mientras el demonio sigue en marcha, llame POST /admin/cache/reload o reinicie el servicio.

نصب PostgreSQL و انتقال از SQLite

Madmail از SQLite (پیش‌فرض) و PostgreSQL پشتیبانی می‌کند؛ MySQL فعلا پشتیبانی نمی‌شود. این راهنما برای Madmail v2 است؛ Madmail روی میزبان نصب است و PostgreSQL را روی همان سرور، با Docker یا به‌صورت مستقیم نصب می‌کنید.

حساب‌ها، تنظیمات و سهمیه‌ها در پایگاه دادهٔ برنامه ذخیره می‌شوند. نامه‌ها در Maildir و صفحه‌های اشتراک مخاطب در sharing.db می‌مانند.

۱. نصب PostgreSQL: یکی از دو روش

فقط یکی از روش‌های زیر را انتخاب کنید. رمزهای نمونه را با رمز تصادفی بلند از حروف و عدد عوض کنید تا نیاز به تغییر نقل‌قول‌های دستورها نباشد؛ رمز کاربر madmail باید در مرحله‌های بعد یکسان باشد.

سیستم‌عامل سرور
روش نصب PostgreSQL

روش اول: Docker

Docker باید نصب و فعال باشد و پورت ۵۴۳۲ میزبان آزاد باشد. این دستور PostgreSQL 17 را با فضای ذخیره‌سازی پایدار اجرا می‌کند؛ پورت ۵۴۳۲ فقط روی همین میزبان در دسترس است.

sudo docker volume create madmail-postgres-data
sudo docker run -d --name madmail-postgres --restart unless-stopped \
    -p 127.0.0.1:5432:5432 \
    -e POSTGRES_PASSWORD=choose-postgres-secret \
    -v madmail-postgres-data:/var/lib/postgresql/data \
    postgres:17

تا نمایش accepting connections صبر کنید و در صورت نیاز دوباره اجرا کنید:

sudo docker exec madmail-postgres pg_isready -h 127.0.0.1 -U postgres

داده‌ها در volume می‌مانند؛ آن را حذف نکنید و جداگانه از PostgreSQL پشتیبان بگیرید. برای این روش، به نصب PostgreSQL روی میزبان نیازی نیست.

نصب با مدیر بستهٔ سیستم‌عامل

Debian / Ubuntu:

sudo apt-get update
sudo apt-get install -y postgresql postgresql-client
sudo systemctl enable --now postgresql

Fedora: مقداردهی اولیه را فقط برای نصب تازه اجرا کنید.

sudo dnf install -y postgresql-server postgresql
sudo postgresql-setup --initdb

در Fedora، فایل /var/lib/pgsql/data/pg_hba.conf را باز کنید و روش احراز هویتِ خط موجود برای 127.0.0.1/32 را به شکل زیر تغییر دهید:

host    all    all    127.0.0.1/32    scram-sha-256
sudo systemctl enable --now postgresql

راهنمای رسمی: PostgreSQL در Docker · PostgreSQL در Fedora

۲. ساخت کاربر و پایگاه داده

با توجه به روش نصب، یکی از دستورهای زیر را اجرا کنید:

نصب مستقیم:

sudo -u postgres psql -v ON_ERROR_STOP=1

Docker:

sudo docker exec -it madmail-postgres psql -U postgres -v ON_ERROR_STOP=1

سپس این دستورهای SQL را وارد کنید؛ choose-a-secret رمز کاربر Madmail است:

CREATE USER madmail WITH PASSWORD 'choose-a-secret';
CREATE DATABASE madmail OWNER madmail;
\q

اتصال و رمز را بررسی کنید؛ رمز کاربر Madmail را هنگام درخواست وارد کنید.

نصب مستقیم:

psql -h 127.0.0.1 -U madmail -d madmail -W -c 'SELECT current_user, current_database();'

Docker:

sudo docker exec -it madmail-postgres psql -h 127.0.0.1 -U madmail -d madmail -W -c 'SELECT current_user, current_database();'

از اینجا به بعد، تنظیمات و فرمان‌های انتقال برای هر دو روش یکسان است.

۳. توقف و پشتیبان‌گیری

Madmail باید از قبل نصب شده باشد. مسیرهای زیر پیش‌فرض‌اند؛ اگر state_dir یا مسیر پیکربندی شما متفاوت است، مسیرهای نمونه را تغییر دهید. ابتدا سرویس را متوقف کنید و از پوشهٔ داده‌ها و فایل پیکربندی پشتیبان بگیرید.

sudo systemctl stop madmail
sudo tar -czf /root/madmail-before-postgres.tar.gz /etc/madmail /var/lib/madmail

این فرمان فقط دو مسیر نوشته‌شده را پشتیبان می‌گیرد. اگر فایل SQLite یا داده‌های شما جای دیگری است، مسیر آن‌ها را هم اضافه کنید. پشتیبان را در جای امن نگه دارید و برای هر انتقال نامی متفاوت بگذارید.

۴. انتقال داده‌های SQLite

برای نصب تازه، این مرحله را رد کنید. برای سرور موجود، در تنظیمات فعلی مسیر dsn را در auth.pass_table ← table sql_table پیدا کنید؛ در مثال زیر /var/lib/madmail/credentials.db است.

sudo madmail --config /etc/madmail/madmail.conf db sqlite-to-postgres \
    --sqlite /var/lib/madmail/credentials.db \
    --dsn 'host=127.0.0.1 port=5432 user=madmail password=choose-a-secret dbname=madmail sslmode=disable' --dry-run

sudo madmail --config /etc/madmail/madmail.conf db sqlite-to-postgres \
    --sqlite /var/lib/madmail/credentials.db \
    --dsn 'host=127.0.0.1 port=5432 user=madmail password=choose-a-secret dbname=madmail sslmode=disable' -y

--dry-run فقط ردیف‌های SQLite را می‌شمارد و اتصال به PostgreSQL را بررسی نمی‌کند. فرمان دوم ساختار جدول‌ها را می‌سازد و داده‌ها را کپی می‌کند. تعداد ردیف‌های مبدأ و کپی‌شده را در خروجی مقایسه کنید.

از یک پایگاه دادهٔ تازه و خالی استفاده کنید. اگر ابزار خطای پر بودن مقصد را داد، پایگاه تازه‌ای بسازید. --force داده‌های قبلیِ جدول‌های قابل انتقال را از مقصد پاک می‌کند؛ برای این راهنما از آن استفاده نکنید.

ابزار داخلی Madmail ساختار جدول‌ها را می‌شناسد؛ نیازی به pgloader نیست. Maildir، صف ارسال، admin_token و sharing.db کپی نمی‌شوند و در همان پوشه می‌مانند. فایل تنظیمات هم خودکار تغییر نمی‌کند.

۵. تغییر تنظیمات

در /etc/madmail/madmail.conf، مقدار driver و dsn را در هر دو بلوک موجود مثل زیر تغییر دهید؛ بقیهٔ گزینه‌ها را نگه دارید و بلوک تکراری نسازید.

auth.pass_table local_authdb {
    auto_create yes
    jit_domain $(primary_domain)
    table sql_table {
        driver postgres
        dsn host=127.0.0.1 port=5432 user=madmail password=choose-a-secret dbname=madmail sslmode=disable
        table_name passwords
    }
}

storage.imapsql local_mailboxes {
    auto_create yes
    driver postgres
    dsn host=127.0.0.1 port=5432 user=madmail password=choose-a-secret dbname=madmail sslmode=disable
    retention 24h
    default_quota 1G
    appendlimit 100M
}

در v2، هر دو بخش از یک پایگاه داده استفاده می‌کنند. نمونهٔ sslmode=disable فقط برای اتصال محلی این راهنماست؛ برای سرور راه دور TLS را تنظیم کنید. رمز داخل DSN در فایل تنظیمات و تاریخچهٔ فرمان‌ها دیده می‌شود؛ دسترسی به آن‌ها را محدود کنید.

۶. راه‌اندازی و بررسی

sudo systemctl start madmail
sudo systemctl status madmail --no-pager
sudo madmail --config /etc/madmail/madmail.conf accounts status

تعداد حساب‌ها را بررسی کنید و با یک حساب قبلی وارد برنامهٔ ایمیل شوید. در صورت خطا، گزارش سرویس را ببینید:

sudo journalctl -u madmail -n 50 --no-pager

در نصب تازه، اولین اجرا جدول‌ها را خودکار می‌سازد. تغییر driver به‌تنهایی داده‌ها را منتقل نمی‌کند و madmail reload هم اتصال پایگاه داده را عوض نمی‌کند؛ سرویس باید دوباره راه‌اندازی شود.

اگر انتقال ناموفق بود، سرویس را متوقف نگه دارید و تنظیمات قبلی SQLite را برگردانید. تا پایان بررسی، فایل SQLite و نسخهٔ پشتیبان را حذف نکنید. اگر داده‌های جدیدی در PostgreSQL ثبت شود، بازگشت به SQLite آن‌ها را منتقل نمی‌کند.
